Qubit เดี่ยว & Bloch sphere

1. bit vs qubit · bra-ket

บิตคลาสสิกเป็นได้แค่ 0 หรือ 1 · qubit เก็บ ส่วนผสม ของทั้งสองไว้ เขียนด้วย bra-ket ว่า ∣0⟩ กับ ∣1⟩ (ket = เวกเตอร์สถานะ)

∣ψ⟩ = a∣0⟩ + b∣1⟩  ·  ∣a∣² + ∣b∣² = 1

misconception อันดับ 1

“superposition (การซ้อนทับ) = เป็น 0 และ 1 พร้อมกัน อ่านได้ทั้งคู่” → ผิด
มันคือ “ส่วนผสมที่ยังไม่มีคำตอบ” เหมือนเหรียญที่กำลังหมุนอยู่ ไม่ใช่เหรียญที่มีสองหน้าให้หยิบ — และเมื่ออ่าน (READ) qubit 1 ตัว ได้ออกมาแค่ 1 บิตธรรมดา เท่านั้น qubit จึงไม่ใช่ “ที่เก็บข้อมูล 2 เท่าฟรี”

2. amplitude = magnitude + relative phase

ค่า a, b เรียกว่า amplitude เป็นจำนวนเชิงซ้อน จึงมี 2 ลูกบิด ต่อหนึ่งวง

ลูกบิดความหมายเชิงภาพอ่าน (READ) แล้วเห็นไหม
magnitude (ขนาด ∣a∣) ความยาวเข็ม / ขนาดวงในของ circle notation เห็น — โอกาสวัดได้ = ∣a∣²
relative phase (เฟสสัมพัทธ์ θ) ทิศของเข็ม (หมุน) — ไม่เปลี่ยนความยาว ไม่เห็นตอนวัดครั้งเดียว แต่เผยตัวตอน interference (การแทรกสอด)
refresher จำนวนเชิงซ้อน

เขียนได้ 2 แบบ: a + bi (พิกัดฉาก) หรือ r·e^(iθ) (พิกัดเชิงขั้ว) — แบบหลังคือแบบที่ตรงกับเข็มนาฬิกา: r = ความยาวเข็ม (magnitude) · θ = ทิศเข็ม (phase)
ที่ต้องใช้จริงมีแค่: ∣r·e^(iθ)∣² = r² → phase ไม่กระทบโอกาสวัด

global vs relative

หมุนทุกวงด้วยมุมเท่ากัน = global phase → วัดผลอย่างไรก็เหมือนเดิม ไม่มีความหมาย
หมุนบางวงเทียบกับวงอื่น = relative phase → มีความหมาย นี่คือเหตุผลที่ PHASE หมุนแค่วง ∣1⟩ ก็พอ

3. circle notation

1 วง = 1 สถานะฐาน · ในวงมีวงในสีทึบกับเข็มหนึ่งอัน — กติกาที่ออกสอบมี 3 ข้อ

  1. รัศมีวงใน = magnitude · พื้นที่วงใน = ความน่าจะเป็น (∣a∣²) — จำเป็น “พื้นที่” ไม่ใช่ “รัศมี”
  2. ทิศเข็ม = phase · มุมบวก = ทวนเข็มนาฬิกา (convention ของวิชานี้)
  3. normalization: พื้นที่ของทุกวงรวมกัน = 1 เสมอ

4. NOT (X) และ HAD (H)

NOT / X — สลับวง ∣0⟩ ↔ ∣1⟩ (สลับทั้งขนาดและเข็ม) · เป็น its own inverse (NOT·NOT = ไม่ทำอะไร)

HAD / H — สร้าง superposition 50/50 จาก ∣0⟩ หรือ ∣1⟩ และเป็น its own inverse เหมือนกัน

H∣0⟩ = (∣0⟩ + ∣1⟩)/√2  ·  H∣1⟩ = (∣0⟩ − ∣1⟩)/√2

ทำไม H∣1⟩ ต้องมีเครื่องหมายลบ — 3 เหตุผล

1. orthogonality (ความตั้งฉาก) — ∣0⟩ กับ ∣1⟩ ตั้งฉากกัน ผลลัพธ์ H∣0⟩ กับ H∣1⟩ ก็ต้องตั้งฉากกันด้วย ลอง inner product: (1·1 + 1·(−1))/2 = 0 ✓ ถ้าเป็นบวกทั้งคู่จะไม่ตั้งฉาก

2. reversibility (ย้อนกลับได้) — ถ้า H∣0⟩ กับ H∣1⟩ ให้ผลเหมือนกันเป๊ะ ก็ย้อนกลับไม่ได้ว่ามาจากอะไร เครื่องหมายลบคือสิ่งเดียวที่แยกสองเส้นทางนี้ออกจากกัน

3. interference — พอ H อีกที เทอมบวกกับเทอมลบหักล้างกัน (destructive) เหลือ ∣0⟩ ตัวเดียว → นี่คือเหตุผลที่ H·H = ไม่ทำอะไร

ทั้งสามเรื่องนี้คือ “เครื่องหมายลบ = เข็มชี้ลง = −1 ในเวกเตอร์ = relative phase 180°” สิ่งเดียวกัน เล่า 3 ภาษา

5. READ และ WRITE

คำสั่งทำอะไรย้อนกลับได้ไหม
READ วัด → สุ่มยุบเหลือ 0 หรือ 1 ตามความน่าจะเป็น · ลบ phase ทิ้งทั้งหมด ไม่ได้ — คำสั่งเดียวในวิชานี้ที่ irreversible (และเป็นตัวเดียวที่สุ่ม)
WRITE ตั้งค่า qubit ให้เป็น ∣0⟩ หรือ ∣1⟩ แบบแน่นอน — ตั้งเป็น superposition ไม่ได้ ไม่ได้ เพราะสร้างจาก READ
WRITE สร้างจาก READ + NOT

WRITE ไม่ใช่คำสั่งพื้นฐานจริงๆ — วิธีทำคือ READ ก่อน (บังคับให้เป็น 0 หรือ 1 แน่ๆ) แล้วถ้าได้ค่าไม่ตรงที่ต้องการ ค่อย NOT · ที่ WRITE ย้อนกลับไม่ได้ก็เพราะข้างในมี READ อยู่นี่เอง

7. PHASE(θ)

หมุนเข็มเฉพาะวง ∣1⟩ ไป θ องศา (ทวนเข็ม = บวก) · ไม่มีผลกับ ∣0⟩ เลย และไม่เปลี่ยนโอกาสวัด เพราะขนาดวงเท่าเดิม

counter-example ที่ต้องจำ

PHASE เป็น reversible แต่ไม่ใช่ its own inverse — PHASE(45°) สองที = PHASE(90°) ไม่ใช่กลับที่เดิม ต้องย้อนด้วย PHASE(−θ)
ข้อยกเว้น: PHASE(180°) = Z ตัวนี้ its own inverse (เพราะ 180+180 = 360 = ครบรอบ)

สถานะที่มีชื่อ 4 ตัว สร้างจาก HAD แล้วต่อ PHASE: ∣+⟩ (0°) · ∣−⟩ (180°) · ∣+Y⟩ (+90°, เข็มชี้ซ้าย) · ∣−Y⟩ (−90°, เข็มชี้ขวา)

ส่วนที่ 1

register หลาย qubit = 2ᴺ วง

N qubit ได้ 2ᴺ วง ไม่ใช่ 2N วง — หนึ่งวงต่อหนึ่งค่าที่ READ ออกมาได้ ไม่ใช่หนึ่งคู่วงต่อ qubit เหตุผล: ถ้าวาดแยก qubit ละ 2 วง จะบรรยาย superposition (การซ้อนทับ) ของกลุ่มไม่ได้ — มันเก็บได้แค่ "แต่ละตัวเป็นยังไง" ไม่เก็บ "ความสัมพันธ์ระหว่างตัว"

แยกเป็น qubit เดี่ยวได้ vs แยกไม่ได้

แยกได้ (product state / สถานะแยกร่าง) — เช่น |0⟩+|2⟩+|4⟩+|6⟩ เท่าๆ กัน สังเกตว่าบิต 0x1 เป็น 0 ทุกวง แปลว่า register นี้ = "0x1 อยู่ที่ |0⟩ แน่นอน" × "0x2, 0x4 อยู่ในซ้อนทับ 50/50" → เขียนแยกทีละ qubit ได้

แยกไม่ได้ = entanglement (การพัวพัน) — เช่น GHZ state (|000⟩+|111⟩)/√2 คือ |0⟩ กับ |7⟩ อย่างละ 50%

อย่าไล่จับคู่ทีละวง ให้มองเป็นคอลัมน์: NOT = flip คอลัมน์นั้นทั้งคอลัมน์ (0↔1 ทุกแถว) แล้วดูว่าแต่ละแถวเลื่อนไปเป็นเลขอะไร · PHASE = เลือกเฉพาะแถวที่คอลัมน์นั้นเป็น 1 · READ = แบ่งตารางเป็นสองฝั่งตามคอลัมน์นั้น

worked example — state ตั้งต้นชุดเดียว ใช้ทั้ง 3 แบบ

สมมติ register 3 qubit อยู่ที่ |1⟩, |2⟩, |4⟩, |7⟩ อย่างละ 25% (วงเท่ากัน 4 วง เข็มชี้ขึ้นหมด):

(ก) NOT ที่ 0x1 — สลับของในแต่ละคู่

คู่ของ 0x1 = (0,1) (2,3) (4,5) (6,7) → ของในวง สลับที่กัน ทั้งขนาดและเข็ม ในตารางไบนารีคือ flip คอลัมน์ 0x1: 1→0, 2→3, 4→5, 7→6 → ดูโค้ด

จำคู่กันไว้

NOT ขยับของ (วงย้ายที่) แต่ PHASE ไม่ขยับของ (วงอยู่ที่เดิม หมุนแค่เข็ม) → ความน่าจะเป็นของทุกผลลัพธ์หลัง PHASE ยังเท่าเดิมเป๊ะ

(ข) PHASE(45°) ที่ 0x2 — หมุนเข็มของ "ฝั่งขวา" ของทุกคู่

คู่ของ 0x2 = (0,2) (1,3) (4,6) (5,7) — สมาชิกที่ index มากกว่าในแต่ละคู่คือตัวที่บิต 0x2 = 1 กลุ่มนั้นคือ |2⟩ |3⟩ |6⟩ |7⟩ ได้เข็มหมุน 45° ทวนเข็ม ที่เหลือไม่แตะ → ดูโค้ด

ทำไม PHASE แตะครึ่งหนึ่ง "เสมอ"

เพราะทุกวงถูกจับคู่หมด และในทุกคู่มีตัวที่บิตนั้นเป็น 1 อยู่ ตัวเดียว → กลุ่ม "บิตนั้น = 1" มี 2ᴺ⁄2 วง = ครึ่งพอดี ไม่ว่ายิงที่ qubit ไหนหรือ register ใหญ่แค่ไหน (ที่ 3 qubit ก็คือ 4 จาก 8 วง แม้บางวงจะว่างอยู่ก็ถือว่าถูกแตะ)

(ค) READ ที่ 0x4 — ตัดครึ่งที่ขัดกับผล แล้ว renormalize

READ ไม่ได้ทำทีละคู่แบบ NOT/PHASE แต่ใช้การแบ่งกลุ่มชุดเดียวกัน: ฝั่ง 0x4 = 0 คือ |0⟩–|3⟩ · ฝั่ง 0x4 = 1 คือ |4⟩–|7⟩ → ดูโค้ด

1 P(อ่านได้ 0) = ผลรวมพื้นที่ฝั่ง 0x4=0 = |1⟩ 25% + |2⟩ 25% = 50%
2 P(อ่านได้ 1) = |4⟩ 25% + |7⟩ 25% = 50%
3 สมมติอ่านได้ 1 → วงฝั่ง 0x4=0 (|0⟩–|3⟩) หายหมด
4 renormalize: ที่เหลือรวมได้ 50% ต้องดันกลับเป็น 100% → หารด้วย 0.5 ทุกวง → |4⟩ 50%, |7⟩ 50%

Teleportation

ย้าย state (สถานะ) ของ qubit หนึ่งไปโผล่ที่อีก qubit หนึ่ง โดยไม่ได้ส่งตัว qubit ไปไหนเลย — ใช้ คู่ entangled 1 คู่ + บิตคลาสสิก 2 บิต เท่านั้น

แกนของบทนี้ — อ่าน 4 บรรทัดนี้ให้เข้าใจก่อน แล้วค่อยเดิน step
  1. CNOT+HAD ฝั่ง Alice = Bell measurement ถามว่า "ความสัมพันธ์ payload–ep เป็นแบบไหนใน 4 แบบ" ไม่ได้ถามว่า payload คืออะไร → ข้อมูลจึงไม่ถูกทำลาย แต่ถูกผลักไปที่ Bob
  2. HAD จำเป็นเพราะ CNOT อย่างเดียวแยก 4 แบบไม่ออก — ความต่างบางคู่ซ่อนอยู่ในเฟส ซึ่ง READ มองไม่เห็น (โยงกลับ Lec02) · HAD = ตัวแปลง "ความต่างเชิงเฟส → ความต่างที่อ่านได้"
  3. READ 2 บิต = สุ่มหยิบ 1 ใน 4 แบบ → qubit ของ Bob = payload ต้นฉบับที่ถูกบิดแบบใดแบบหนึ่ง
  4. 2 บิตคลาสสิก = ใบสั่งว่าบิดแบบไหน → Bob บิดกลับ → เหตุผลที่ไม่เร็วกว่าแสง

ทุกอย่างที่เหลือในหน้านี้คือรายละเอียดของ 4 บรรทัดนี้ ถ้าตอบข้อสอบไม่ได้ ให้ย้อนกลับมาอ่านตรงนี้

1 teleportation คือ / ไม่ใช่อะไร

คือไม่ใช่
ย้าย สถานะ (magnitude + relative phase ครบทุกหลัก) ไปที่ qubit ปลายทาง ย้าย สสาร / อะตอม / ตัว qubit
ต้นฉบับ ถูกทำลาย เสมอ (Alice READ ทิ้งทั้ง payload และ ep) คัดลอก — ถ้าไม่ทำลายต้นฉบับจะละเมิด no-cloning ทันที
ต้องมีช่องคลาสสิกส่ง 2 บิต จึงเร็วได้ไม่เกินความเร็วแสง สื่อสารเร็วกว่าแสง — ก่อนได้ 2 บิต Bob ถือของที่ดูเหมือนสุ่มล้วน
Alice ไม่จำเป็นต้องรู้ ว่า payload คือสถานะอะไร การวัดแล้วบอกค่าไปให้ปลายทางสร้างใหม่ (ทำแบบนั้นไม่ได้ เพราะ state มีข้อมูลต่อเนื่องไม่จำกัด)
ตัวละคร 3 qubit

alice = payload (ตัวที่จะถูกส่ง) · ep = ครึ่งหนึ่งของคู่ entangled ที่ Alice ถือ · bob = อีกครึ่งที่ Bob ถือ
Alice ถือ 2 ตัว (alice, ep) · Bob ถือ 1 ตัว (bob) — คู่ ep–bob เปรียบเหมือน "สาย LAN ควอนตัม" ที่วางไว้ล่วงหน้า

2 วงจร teleportation ฉบับสมบูรณ์

← เลื่อนดูได้

อ่านวงจรเป็น 5 กล่อง
  1. entangle — HAD บน ep แล้ว CNOT(ep→bob) = สร้าง Bell pair
  2. prep payload 45° — H → φ(45°) → H บน alice เท่านั้น (ในข้อสอบ payload เป็นอะไรก็ได้ ตัวนี้แค่ตัวอย่าง)
  3. send — CNOT(alice→ep) → HAD(alice) → READ ทั้ง alice และ ep (สายจางลง = ถูกทำลาย)
  4. receive 180° — บน bob: ⊕ แล้ว φ(180°) ทั้งคู่ถูกคุมด้วยลูกศรประฟ้าจากบิตคลาสสิก
  5. verify −45° — H → φ(−45°) → H → READ = prep payload แบบย้อนกลับ

🔴 สัญลักษณ์ที่ต้องจำไปสอบ: ▷ = WRITE ที่หัวสาย · ครึ่งวงกลม = READ · ลูกศรประฟ้าชี้ลง = classical control · กล่องมีชื่อคร่อม gate = การจัดกลุ่มขั้นตอน

3 circle notation 8 วง — สถานะ ณ 5 จุด

3 qubit → 2³ = 8 basis state = 8 วง · น้ำหนักบิต: alice = 1, ep = 2, bob = 4
เช่น |5⟩ = 101₂ → bob = 1, ep = 0, alice = 1 · พื้นที่วง = ความน่าจะเป็น · เข็ม = phase (ทวนเข็ม = มุมบวก)

จุดที่ 1 — เริ่มต้น (ก่อนทุกอย่าง): ทั้งสามเป็น |0⟩ → มีวงเดียว

จุดที่ 2 — หลัง Bell pair (จบกล่อง entangle): เหลือ |0⟩ กับ |6⟩ อย่างละ 50%

|0⟩ = 000, |6⟩ = 110 → ep กับ bob เท่ากันเสมอ (อ่านได้ 50/50 แต่ตรงกันแน่นอน) ส่วน alice ยังเป็น |0⟩ เดี่ยวๆ

จุดที่ 3 — หลังเตรียม payload (จบกล่อง prep payload): เพิ่มมาเป็น 4 วง

วง alice=1 (|1⟩, |7⟩) เข็มหมุนไป −90° (ตามเข็ม) เทียบกับวง alice=0 · อ่านเฉพาะ alice = 85.4% |0⟩ + 14.6% |1⟩ ที่ phase −90° — นี่คือ payload ที่จะส่ง · วง |2⟩|3⟩|4⟩|5⟩ ยังว่าง = ep กับ bob ยังผูกกันอยู่

จุดที่ 4 — หลัง CNOT + HAD (จบ Step 3.2): ครบทั้ง 8 วง

อ่านเป็น คอลัมน์: คอลัมน์หนึ่ง = ค่าคู่ (alice, ep) หนึ่งค่า · ในคอลัมน์นั้น วงบน = bob 0, วงล่าง = bob 1
col1 (a=0,ep=0) = |0⟩/|4⟩ · col2 (a=1,ep=0) = |1⟩/|5⟩ · col3 (a=0,ep=1) = |2⟩/|6⟩ · col4 (a=1,ep=1) = |3⟩/|7⟩

จุดที่ 5 — หลัง READ ของ Alice (จบ Step 3.3): เหลือ คอลัมน์เดียว (รูปนี้สุ่มได้ col4: alice=1, ep=1)

READ = เลือกคอลัมน์มา 1 คอลัมน์ วงนอกคอลัมน์ magnitude เป็นศูนย์หมด แล้ว normalize ใหม่ → กลับมาเป็น 85.4/14.6 เท่าเดิม แค่ สลับหัวท้าย (โดน NOT) และเข็มกลับด้าน (โดน PHASE 180°)

4 เดิน 5 step

Step 1 — สร้าง Bell pair · ep.had(); bob.cnot(ep); → ดูโค้ด
HAD+CNOT คู่นี้คือสูตรสร้าง Bell pair เดียวกับ Lec03 → ep กับ bob สุ่ม 50/50 แต่ตรงกันเสมอ

Step 2 — เตรียม payload · alice.write(0); alice.had(); alice.phase(45); alice.had();
ในงานจริง payload มาจากไหนก็ได้ (คำนวณมา / entangle กับส่วนอื่น) — บทนี้เลือก H–φ45–H เพราะได้ pattern ที่อ่านง่ายในวง

Step 3.1 — เชื่อม payload เข้ากับคู่ entangled · ep.cnot(alice); (control = alice, target = ep)
ในภาษาวง = สลับวงในคู่ที่ alice = 1 (|1⟩↔|3⟩ และ |5⟩↔|7⟩) · หลังจากนี้เหลือเฉพาะวงที่ XOR ของทั้งสามบิต = 0 (000, 011, 101, 110) → จาก entangle 2 ตัว กลายเป็น ก้อน entangled 3 ตัว

⚠️ ตรงนี้คนงงกันเยอะ อ่านช้าๆ

ถึงตรงนี้ payload ยังไม่ได้ย้ายไปไหน — CNOT แค่ผูกมันเข้ากับอีกสองตัว ส่วนที่ทำให้ข้อมูล "ไหล" ไปหา Bob จริงๆ คือ HAD ใน Step 3.2 ต่างหาก ถ้าอ่าน Step 3.2 แล้วยังไม่เข้าใจ ให้ย้อนกลับไปอ่าน "แกน 4 บรรทัด" ข้อ 1–2 อีกรอบก่อน แล้วค่อยกลับมา

Step 3.2 — HAD บน payload · alice.had(); ← หัวใจของทั้งบท

ทำไมต้อง HAD ก่อน READ

หลัง CNOT อย่างเดียว สถานะที่ Bob "อาจจะได้" มีอยู่ 4 แบบ แต่บางคู่ในนั้นต่างกันแค่เฟส — และ READ อ่านเฟสไม่เห็นเลย (Lec02: READ เห็นแค่ขนาดวง ไม่เห็นทิศเข็ม) ถ้า Alice READ ตอนนี้ เธอจะแยกไม่ออกว่าเป็นแบบไหน แล้วข้อมูล magnitude+phase ของ payload ก็หายไปเฉยๆ

HAD คือเครื่องแปลง "ความต่างเชิงเฟส → ความต่างที่อ่านได้" (interference: วงที่เฟสตรงกันเสริมกัน วงที่เฟสตรงข้ามหักล้างกัน) พอผ่าน HAD แล้ว ทั้ง 4 แบบไปอยู่คนละคอลัมน์ที่ READ แยกออก → 2 บิตของ Alice จึงมีความหมายจริง

อีกมุมหนึ่ง: CNOT + HAD + READ 2 ตัว = Bell measurement คือการถามว่า "payload กับ ep สัมพันธ์กันแบบไหนใน 4 แบบ" ไม่ใช่ถามว่า "payload คืออะไร" → คำถามที่ไม่แตะเนื้อของ payload ข้อมูลจึงไม่ถูกทำลาย แต่ถูกผลักข้ามไปที่ bob

Step 3.3 — READ ทั้งสองตัวของ Alice · bit_p = alice.read(); bit_n = ep.read();
ทำลาย qubit ทั้งสองอย่างถาวร — และต้องทำลาย ไม่งั้นก็เท่ากับ copy สถานะ (ผิด no-cloning) · ผลลัพธ์ = สุ่มเลือก 1 ใน 4 คอลัมน์ ได้ 2 บิตคลาสสิก พอดี

ผลลัพธ์: bob กลับมาเป็น payload เดิมเป๊ะ — 85.4% |0⟩ + 14.6% |1⟩ ที่ phase −90°

bi² = bi  (เพราะบิตมีแค่ 0 กับ 1: 0²=0, 1²=1)

ตั้ง b = Σ 2ⁱ·bᵢ แล้วกระจายกำลังสอง จะได้เทอม 2 แบบ:

เทอมเดี่ยว (2ⁱbᵢ)² = 22i·bᵢ² = 22i·bᵢ
เทอมคู่ i<j 2·(2ⁱbᵢ)(2ʲbⱼ) = 2i+j+1·bᵢbⱼ

กาง 2 บิต (b = b₀ + 2b₁):

b² = b₀ + 4b₁ + 4b₀b₁

กาง 3 บิต (b = b₀ + 2b₁ + 4b₂):

b² = b₀ + 4b₁ + 16b₂ + 4b₀b₁ + 8b₀b₂ + 16b₁b₂

วิธีเช็กเร็วในห้องสอบ — แทนค่า

b = 5 = 101₂ → b₀=1, b₁=0, b₂=1 → 1 + 0 + 16 + 0 + 8 + 0 = 25 ✓

b = 7 = 111₂ → ทุกบิต = 1 → 1 + 4 + 16 + 4 + 8 + 16 = 49 ✓

แทน 2 ค่านี้ผ่านแล้วมั่นใจได้เลยว่ากางถูก

วงจร a.addSquared(b) ในสไลด์ (12 คอลัมน์) ก็คือการแปลสูตร 2 บิตนี้เป็น gate ตรงๆ: b₀ เป็น control → a += 1 · b₀∧b₁ เป็น control → a += 2 ทำสองรอบ (= +4) · b₁ เป็น control → a += 4

ทำไม b = b*b ทำไม่ได้ แต่ a += b*b ได้

b = b*b — ไม่มีชุด operation ที่ reversible ชุดไหนทำได้เลย เพราะเสีย sign bit (บิตเครื่องหมาย) ไปเสมอ (b และ −b ให้ผลเดียวกัน → ย้อนกลับแยกไม่ออก)

a += b*b — ไม่มีปัญหา เพราะตัวย้อนกลับของมันคือ a -= b*b เฉยๆ และ b ยังอยู่ครบไม่ถูกแตะ

register 3 บิตแบบ two's complement · หลังรันวงจร negate กับค่า 100 จะได้อะไร?
ถูก — flip ได้ 011 แล้ว +1 กลับมาเป็น 100 · +4 ล้นช่วงของ 3 บิต ผลจึงค้างที่ −4
ยังไม่ใช่ — flip ทุกบิตได้ 011 แต่ยังต้อง +1 ต่ออีก → 100 = −4

Quantum-Conditional Execution

คลาสสิก: CPU ต้องอ่านค่าก่อน แล้วค่อยตัดสินใจว่าจะรัน logic หรือไม่ · QPU: ค่าหนึ่งเป็นทั้งเซ็ตและไม่เซ็ตพร้อมกันได้ → operation ที่ขึ้นกับค่านั้นจึงทั้งรันและไม่รันพร้อมกันใน superposition — ใช้ได้ถึงระดับรัน digital logic ก้อนใหญ่แบบมีเงื่อนไข

ทริกที่ต้องจำ — b.not(~1)

ปัญหา: control (●) อ่านได้แค่ "บิตนี้เป็น 1" · แต่เงื่อนไข b == 1 คือ 01₂ ซึ่งมีเลข 0 ปนอยู่

ทริก: พลิกบิตที่ควรเป็น 0 ให้เป็น 1 ก่อน (b.not(~1) = พลิกทุกบิตยกเว้น 0x1) → เงื่อนไขกลายเป็น "ทุกบิตของ b เป็น 1" ใช้ทุกบิตเป็น control ได้เลย → ใช้เสร็จแล้วพลิกกลับคืน → ดูโค้ด

Phase-Encoded Results

ย้ายผลลัพธ์ของการคำนวณไปเก็บใน relative phase (เฟสสัมพัทธ์) ของ register อินพุตเดิม แทนที่จะเก็บใน magnitude — สิ่งที่บิตธรรมดาทำไม่ได้เลย · magnitude ไม่ขยับสักวง แต่เข็มบางวงกลับด้าน

นี่คือรากของ oracle ในอัลกอริทึมยุคหลัง (เช่น Grover) และเป็นทักษะที่ทำให้คำตอบ "รอด" การ READ ได้

Scratch qubit & abs(a)

abs จับคู่หลายอินพุตไปเอาต์พุตเดียว (−3 และ 3 → 3) = ไม่ 1-ต่อ-1 = ไม่ reversible → ทำตรงๆ ไม่ได้ ต้องเพิ่ม scratch qubit (คิวบิตทด) เข้ามารับข้อมูลที่จะหาย (ในที่นี้คือ sign bit)

scratch ไม่ใช่การ copy

อ่านจาก circle notation: ถ้าไม่มี scratch ผังจะมีแค่แถวเดียว การย้ายวงของค่าลบไปทับช่องค่าบวกจะทำลาย magnitude/phase ที่อยู่ตรงนั้นอยู่แล้ว · scratch เพิ่มอีกแถวหนึ่ง ให้ย้ายลงไปได้โดยของเดิมไม่ถูกแตะ

ผลข้างเคียง: scratch จะ entangled (พัวพัน) กับ output register เสมอ — ไม่ใช่สำเนาแยกอิสระ · จึง READ ทิ้งไม่ได้ (จะทำลาย output ที่มันช่วยสร้าง) และมันแทบไม่เคยกลับไป |0⟩ เอง

Uncomputing

compute → use → uncompute

← เลื่อนดูได้

ทำไมคำตอบไม่หายไปตอน uncompute

ถ้า uncompute ทันทีหลัง compute → ได้ scratch คืนก็จริง แต่ล้างคำตอบทิ้งไปด้วย · กุญแจคือต้อง ใช้ผลลัพธ์ก่อน (เช่น b += abs(a) หรือใช้ CNOT ก๊อปเข้าไปที่ b ซึ่งเริ่มที่ 0) แล้วค่อย uncompute

ผลรวม: operation ก้อนใหญ่ทั้งก้อนยัง reversible ทั้งที่ abs เองไม่ reversible · scratch กลับเป็น |0⟩ ที่ disentangled แล้ว เอาไปใช้ต่อได้

ถ้าผลถูกเก็บไว้ใน relative phase ของ output register เฟสนั้นจะรอดจาก uncompute (เพราะขั้น uncompute ไม่ไปยุ่งกับเฟส)

Toffoli = NAND ของโลกควอนตัม

ในโลกดิจิทัล มี NAND ตัวเดียวก็สร้าง AND/OR/NOT/XOR ได้หมด · ในโลกควอนตัมตัวที่รับบทนี้คือ multiple-condition CNOT = Toffoli — เหมือน NAND ตรงที่เพิ่ม/ลดจำนวน condition input ได้

c = c XOR (a AND b)

ต่างจาก NAND ตรงไหน

NAND เขียนทับ output ทิ้ง → input หาย → irreversible · Toffoli เอาผล a AND b ไป XOR ใส่ค่า c ที่มีอยู่เดิม และ a, b ยังวิ่งออกมาเหมือนเดิมครบ → ย้อนกลับได้

ผลข้างเคียงของ "XOR ใส่ค่าเดิม": วงจรทำ c = c XOR f(a,b) เสมอ จึงเท่ากับ c = f(a,b) ก็ต่อเมื่อ c เริ่มที่ |0⟩ — นี่แหละคือที่มาของ scratch qubit ในตารางข้างล่าง

Pitfalls

ลิสต์ลิงก์กลับไปจุดจริงในเนื้อหา — ไม่เขียนเนื้อซ้ำที่นี่

จุดที่คนมักพลาด

  • Lec01 · QPU คืออะไร — “QPU มาแทน CPU / เร็วกว่าทุกงาน” ผิด มันคือ co-processor ที่เก่งบางงาน
  • Lec01 · QPU คืออะไร — “ต้องเก่งฟิสิกส์ก่อนถึงเขียนโปรแกรมได้” ผิด (สไลด์เทียบกับ C++ กับทรานซิสเตอร์)
  • Lec02 · ข้อ 1 bit vs qubit — “superposition = เป็น 0 และ 1 พร้อมกัน อ่านได้ทั้งคู่” ผิด · qubit 1 ตัวอ่านได้ 1 บิตเท่านั้น
  • Lec02 · ข้อ 2 amplitude — “phase เปลี่ยน → โอกาสวัดเปลี่ยน” ผิด phase ไม่แตะ magnitude² · กับดักหลักของ Lec02
  • Lec02 · ข้อ 3 circle notation — จำผิดว่า “รัศมี = ความน่าจะเป็น” ของจริงคือ พื้นที่
  • Lec02 · ข้อ 5 READ/WRITE — “WRITE ตั้ง superposition ได้” ผิด ตั้งได้แค่ ∣0⟩ / ∣1⟩
  • Lec02 · ข้อ 6 QRNG — “รัน QRNG บน simulator = สุ่มแท้” ผิด simulator ยังใช้ PRNG
  • Lec02 · ข้อ 7 PHASE — “gate ควอนตัมทุกตัวเป็น its own inverse” ผิด PHASE(θ) ต้องย้อนด้วย PHASE(−θ)
  • Lec02 · ข้อ 8 no-cloning — “ก๊อป qubit เก็บไว้ก่อนแล้วค่อยวัด” ทำไม่ได้ ไม่มีคำสั่ง COPY
  • Lec03 · 2ᴺ วง — เข้าใจผิดว่า 2 qubit วาด 2 วงต่อ qubit; ของจริง N qubit = 2ᴺ วง (เคส 2 qubit ที่ได้ 4 เท่ากันเป็นเรื่องบังเอิญ)
  • Lec03 · operator pairs — สลับกันระหว่าง "NOT ขยับของ" กับ "PHASE ไม่ขยับของ"; PHASE ไม่เปลี่ยนความน่าจะเป็นเลย
  • Lec03 · PHASE ครึ่งหนึ่ง — คิดว่า PHASE แตะทุกวง; แตะเฉพาะครึ่งที่บิตนั้น = 1 เสมอ ไม่ว่า register ใหญ่แค่ไหน
  • Lec03 · READ ใน register — คิดว่า READ qubit เดียวยุบทั้ง register; จริงๆ ตัดครึ่งที่ขัดกับผลแล้ว renormalize qubit ที่เหลือยังซ้อนทับอยู่
  • Lec03 · ชื่อสาย — เรียกสายว่า Q1/Q2/Q3; ต้องเรียกตามน้ำหนักบิต 0x1/0x2/0x4 และเส้นบนสุด = 0x1 (LSB)

สไลด์ผิดตรงไหน

  • Lec02 · สไลด์ p71 — เขียนว่า “The Z-axis is a horizontal axis” ผิด · Z คือแกนตั้ง (∣0⟩→∣1⟩) ขัดกับประโยคถัดไปของสไลด์เอง
  • Lec02 · สไลด์ p69 — เขียนว่า “ROTX(π/2) เอียง ∣0⟩ ไป ∣+⟩” ผิด · ของจริง ROTY(π/2)∣0⟩ = ∣+⟩ ส่วน ROTX(π/2)∣0⟩ = ∣−Y⟩ (ใจความที่ออกสอบไม่เปลี่ยน: ทั้งคู่ให้ 50/50 ต่างกันที่ phase)
  • Lec02 · สไลด์ p66 — ระบายไฮไลต์แค่ ∣3⟩ ∣5⟩ ∣7⟩ ตกวง ∣1⟩ ไป · ของจริง PHASE กระทบครึ่งหนึ่ง = 4 วง (เป็นแค่การระบายสีตกหล่น ไม่ใช่เนื้อหาผิด)
  • convention ที่ต้องยึดทุกบท — มุมบวก = ทวนเข็มนาฬิกา (ยืนยันจากสไลด์ p64/p66) สามัญสำนึกว่า “ตามเข็ม” ผิด
  • วิธีรับมือตอนสอบ — ถ้าข้อสอบอ้างสไลด์ตรงๆ ให้ ตอบตามสไลด์ แต่รู้ของจริงไว้เผื่อโจทย์ถามเชิงเข้าใจ
  • Lec03 · PHASE ใน register — สไลด์ Lec03 หน้า 66 (PHASE ที่ 0x1) แถวบนสุดระบายไฮไลต์แค่ |3⟩ |5⟩ |7⟩ ตกวง |1⟩ ไป — เป็นการระบายสีตกหล่น ไม่ใช่เนื้อหาผิด (zoom แล้วเข็มของ |1⟩ เอียงจริง) ของจริงต้องครบ 4 วงตามกฎ "PHASE แตะครึ่งหนึ่ง"
