Lec03 · ทวนให้ครบ ไม่ปูใหม่

Multi-qubit & Entanglement

ครึ่งแรก: register หลาย qubit เขียนเป็นวงยังไง และ gate 1 qubit ทำงานใน register ยังไง (operator pairs) — กลไกกลางของทั้งคาบ

ส่วนที่ 1

register หลาย qubit = 2ᴺ วง

N qubit ได้ 2ᴺ วง ไม่ใช่ 2N วง — หนึ่งวงต่อหนึ่งค่าที่ READ ออกมาได้ ไม่ใช่หนึ่งคู่วงต่อ qubit เหตุผล: ถ้าวาดแยก qubit ละ 2 วง จะบรรยาย superposition (การซ้อนทับ) ของกลุ่มไม่ได้ — มันเก็บได้แค่ "แต่ละตัวเป็นยังไง" ไม่เก็บ "ความสัมพันธ์ระหว่างตัว"

กับดักเลข

2 qubit → 2×2 = 4 และ 2² = 4 บังเอิญเท่ากัน ห้ามจำจากเคสนี้ 3 qubit → 2×3 = 6 แต่ของจริง 2³ = 8 วง

ตารางนี้คือเครื่องมือ

ทั้งส่วน operator pairs ข้างล่างใช้ตารางนี้ตัวเดียวจบ — gate 1 qubit = ทำอะไรบางอย่างกับ "คอลัมน์" ของตัวเอง

ส่วนที่ 2

แยกเป็น qubit เดี่ยวได้ vs แยกไม่ได้

แยกได้ (product state / สถานะแยกร่าง) — เช่น |0⟩+|2⟩+|4⟩+|6⟩ เท่าๆ กัน สังเกตว่าบิต 0x1 เป็น 0 ทุกวง แปลว่า register นี้ = "0x1 อยู่ที่ |0⟩ แน่นอน" × "0x2, 0x4 อยู่ในซ้อนทับ 50/50" → เขียนแยกทีละ qubit ได้

แยกไม่ได้ = entanglement (การพัวพัน) — เช่น GHZ state (|000⟩+|111⟩)/√2 คือ |0⟩ กับ |7⟩ อย่างละ 50%

เหตุผลที่แยกไม่ได้แบบเห็นภาพ: ถ้าทั้ง 3 ตัวต่างคนต่างโยนเหรียญอิสระ ต้องมีโอกาสได้ 010 หรือ 101 บ้าง แต่ state นี้ไม่เคยให้ผลนอกจาก 000 กับ 111 → ผลของแต่ละตัวผูกกันอยู่ ไม่มีคำตอบว่า "qubit ตัวแรกอยู่สถานะอะไร" แยกเดี่ยวๆ

ประโยคออกสอบ

superposition เป็นสมบัติของ qubit เดี่ยว · entanglement เป็นสมบัติของความสัมพันธ์ (ของทั้งระบบ) — qubit เดี่ยวๆ entangle กับตัวเองไม่ได้ ต้องมีอย่างน้อย 2 ตัว

ส่วนที่ 3

กติกาการวาด register: ตั้งชื่อสายตามน้ำหนักบิต

สายในวงจรไม่ตั้งชื่อ Q1, Q2, Q3 แต่ตั้งเป็น 0x1, 0x2, 0x4 … (8 ตัวเรียกรวมว่า qubyte ไปถึง 0x80)

ทำไมต้องแบบนี้

เพื่อให้วงจรกับ circle notation ตรงกันโดยไม่ต้องแปลง — เห็น 0x2 บนวงจร ก็เปิดตารางไบนารีดูคอลัมน์ 0x2 ได้ทันทีว่ากระทบวงไหน ถ้าตั้งชื่อ Q1/Q2/Q3 ต้องมานั่งจำอีกชั้นว่า Q2 คือน้ำหนักเท่าไร (แล้วมักสลับ)

ส่วนที่ 4 · หัวใจของบท

operator pairs — gate 1 qubit ทำงานใน register ยังไง

gate 1 qubit ที่ยิงใส่ register ไม่ได้แตะทีละวง แต่แตะทีละ คู่: จับวงที่ index ต่างกันเท่าน้ำหนักบิตของ qubit ที่ยิง มาเข้าคู่กัน — 8 วง → ได้ 4 คู่เสมอ

ยิงที่คู่ของวงในตารางไบนารี
0x1 (0,1) (2,3) (4,5) (6,7) คู่ที่ต่างกันแค่คอลัมน์ 0x1
0x2 (0,2) (1,3) (4,6) (5,7) คู่ที่ต่างกันแค่คอลัมน์ 0x2
0x4 (0,4) (1,5) (2,6) (3,7) คู่ที่ต่างกันแค่คอลัมน์ 0x4
ทริกไบนารี

อย่าไล่จับคู่ทีละวง ให้มองเป็นคอลัมน์: NOT = flip คอลัมน์นั้นทั้งคอลัมน์ (0↔1 ทุกแถว) แล้วดูว่าแต่ละแถวเลื่อนไปเป็นเลขอะไร · PHASE = เลือกเฉพาะแถวที่คอลัมน์นั้นเป็น 1 · READ = แบ่งตารางเป็นสองฝั่งตามคอลัมน์นั้น

worked example — state ตั้งต้นชุดเดียว ใช้ทั้ง 3 แบบ

สมมติ register 3 qubit อยู่ที่ |1⟩, |2⟩, |4⟩, |7⟩ อย่างละ 25% (วงเท่ากัน 4 วง เข็มชี้ขึ้นหมด):

(ก) NOT ที่ 0x1 — สลับของในแต่ละคู่

คู่ของ 0x1 = (0,1) (2,3) (4,5) (6,7) → ของในวง สลับที่กัน ทั้งขนาดและเข็ม ในตารางไบนารีคือ flip คอลัมน์ 0x1: 1→0, 2→3, 4→5, 7→6 → ดูโค้ด

จำคู่กันไว้

NOT ขยับของ (วงย้ายที่) แต่ PHASE ไม่ขยับของ (วงอยู่ที่เดิม หมุนแค่เข็ม) → ความน่าจะเป็นของทุกผลลัพธ์หลัง PHASE ยังเท่าเดิมเป๊ะ

(ข) PHASE(45°) ที่ 0x2 — หมุนเข็มของ "ฝั่งขวา" ของทุกคู่

คู่ของ 0x2 = (0,2) (1,3) (4,6) (5,7) — สมาชิกที่ index มากกว่าในแต่ละคู่คือตัวที่บิต 0x2 = 1 กลุ่มนั้นคือ |2⟩ |3⟩ |6⟩ |7⟩ ได้เข็มหมุน 45° ทวนเข็ม ที่เหลือไม่แตะ → ดูโค้ด

ทำไม PHASE แตะครึ่งหนึ่ง "เสมอ"

เพราะทุกวงถูกจับคู่หมด และในทุกคู่มีตัวที่บิตนั้นเป็น 1 อยู่ ตัวเดียว → กลุ่ม "บิตนั้น = 1" มี 2ᴺ⁄2 วง = ครึ่งพอดี ไม่ว่ายิงที่ qubit ไหนหรือ register ใหญ่แค่ไหน (ที่ 3 qubit ก็คือ 4 จาก 8 วง แม้บางวงจะว่างอยู่ก็ถือว่าถูกแตะ)

(ค) READ ที่ 0x4 — ตัดครึ่งที่ขัดกับผล แล้ว renormalize

READ ไม่ได้ทำทีละคู่แบบ NOT/PHASE แต่ใช้การแบ่งกลุ่มชุดเดียวกัน: ฝั่ง 0x4 = 0 คือ |0⟩–|3⟩ · ฝั่ง 0x4 = 1 คือ |4⟩–|7⟩ → ดูโค้ด

1 P(อ่านได้ 0) = ผลรวมพื้นที่ฝั่ง 0x4=0 = |1⟩ 25% + |2⟩ 25% = 50%
2 P(อ่านได้ 1) = |4⟩ 25% + |7⟩ 25% = 50%
3 สมมติอ่านได้ 1 → วงฝั่ง 0x4=0 (|0⟩–|3⟩) หายหมด
4 renormalize: ที่เหลือรวมได้ 50% ต้องดันกลับเป็น 100% → หารด้วย 0.5 ทุกวง → |4⟩ 50%, |7⟩ 50%
ระวัง

READ qubit เดียว ไม่ยุบทั้ง register — 0x1 กับ 0x2 ยังซ้อนทับอยู่ (|4⟩ กับ |7⟩ ยังต่างกัน) มันแค่ตัดความเป็นไปได้ครึ่งหนึ่งทิ้ง แล้วเกลี่ยส่วนที่เหลือใหม่

gateทำอะไรกับคู่แตะกี่วงความน่าจะเป็นเปลี่ยนไหม
NOT สลับของสองฝั่งของทุกคู่ ทุกวง (8) ย้ายที่ แต่ค่ารวมเท่าเดิม
PHASE หมุนเข็มฝั่งที่บิต = 1 ครึ่งเดียว (4) ไม่เปลี่ยนเลย
READ เลือกฝั่งเดียวของทุกคู่ ทิ้งอีกฝั่ง ลบทิ้งครึ่งหนึ่ง (4) เปลี่ยน — ต้อง renormalize
ส่วนที่ 5

พอ qubit เยอะ ภาพนี้ก็ใช้ไม่ไหว

จำนวนวงโตแบบเลขชี้กำลัง — 32 qubit = 2³² = 4,294,967,296 วง วาดไม่ไหวและตาก็ดูไม่ทัน QCEngine เลยมีโหมด qc_options.color_by_phase = true ที่เลิกวาดเข็มแล้วใช้สีแทนเฟส เหลือแค่ขนาดวง + สี → กวาดตาเห็นแพทเทิร์นของ state ใหญ่ๆ ได้ (เป็นแค่วิธี "มองภาพ" ไม่ใช่ฟิสิกส์ใหม่)

ทวนเร็ว: register 4 qubit ยิง PHASE(90°) ที่ 0x8 กระทบกี่วง และวงไหนบ้าง?

4 qubit = 16 วง → กระทบครึ่งหนึ่ง = 8 วง คือกลุ่มที่บิต 0x8 = 1 นั่นคือ |8⟩ ถึง |15⟩ (ค่าตั้งแต่ 8 ขึ้นไปคือค่าที่บิตน้ำหนัก 8 ติดอยู่) — ความน่าจะเป็นทุกวงเท่าเดิม

register 3 qubit ยิง NOT ที่ 0x4 ตอนตั้งต้นอยู่ที่ |1⟩ 100% จะไปอยู่ที่วงไหน?
ถูก — flip คอลัมน์ 0x4 ของแถว 001 ได้ 101 = |5⟩ (คู่ของ 0x4 คือ (1,5))
ยัง — NOT ที่ 0x4 จับคู่ (0,4) (1,5) (2,6) (3,7) → |1⟩ ไปที่ |5⟩ (บวก/ลบ 4 นั่นเอง)
state (|000⟩+|111⟩)/√2 อธิบายให้ตรงตามภาษาที่ออกสอบ ควรพูดว่ายังไง?
ใช่ — superposition = สมบัติ qubit เดี่ยว / entanglement = สมบัติของทั้งระบบ
ไม่ใช่ — GHZ ให้ผลได้แค่ 000 กับ 111 ไม่มีทางได้ 010 → แยกทีละ qubit ไม่ได้ = entangle (และ 3 qubit ต้องวาด 8 วงเสมอ)

รวมไว้ที่เดียว

โค้ด ↔ สัญลักษณ์วงจร

ทุกหัวข้อในสรุปที่มีโค้ด จะมีลิงก์ "→ ดูโค้ด" เด้งมาที่แถวของตัวเองในตารางนี้

คำสั่ง (QCEngine / QASM)สัญลักษณ์วงจรทำอะไร
 
qc.reset(3);
var reg = qint.new(3, 'reg');
reg.write(0);
สร้าง register 3 qubit (8 วง) แล้วเซ็ตค่าเริ่มเป็น 0 — สายชื่อตามน้ำหนักบิต 
reg.not(0x1);
NOT ที่ qubit 0x1 — สลับของในทุกคู่ (0,1) (2,3) (4,5) (6,7) 
reg.phase(45, 0x2);
PHASE 45° ที่ qubit 0x2 — หมุนเข็มเฉพาะครึ่งที่บิต 0x2 = 1 (|2⟩ |3⟩ |6⟩ |7⟩) 
var v = reg.read(0x4);
READ เฉพาะ qubit 0x4 — ตัดครึ่งที่ขัดกับผลทิ้งแล้ว renormalize (ไม่ยุบทั้ง register)

Pitfalls

ลิสต์ลิงก์กลับไปจุดจริงในเนื้อหา — ไม่เขียนเนื้อซ้ำที่นี่

จุดที่คนมักพลาด

  • ยังไม่มีรายการ — แต่ละ ticket เติมของตัวเองตอนเขียนหน้านั้น
  • Lec03 · 2ᴺ วง — เข้าใจผิดว่า 2 qubit วาด 2 วงต่อ qubit; ของจริง N qubit = 2ᴺ วง (เคส 2 qubit ที่ได้ 4 เท่ากันเป็นเรื่องบังเอิญ)
  • Lec03 · operator pairs — สลับกันระหว่าง "NOT ขยับของ" กับ "PHASE ไม่ขยับของ"; PHASE ไม่เปลี่ยนความน่าจะเป็นเลย
  • Lec03 · PHASE ครึ่งหนึ่ง — คิดว่า PHASE แตะทุกวง; แตะเฉพาะครึ่งที่บิตนั้น = 1 เสมอ ไม่ว่า register ใหญ่แค่ไหน
  • Lec03 · READ ใน register — คิดว่า READ qubit เดียวยุบทั้ง register; จริงๆ ตัดครึ่งที่ขัดกับผลแล้ว renormalize qubit ที่เหลือยังซ้อนทับอยู่
  • Lec03 · ชื่อสาย — เรียกสายว่า Q1/Q2/Q3; ต้องเรียกตามน้ำหนักบิต 0x1/0x2/0x4 และเส้นบนสุด = 0x1 (LSB)
